## 📌 درباره پروژه

**زرین‌پال آنالیتیکس** یک داشبورد تحلیلی مبتنی بر هوش مصنوعی است که از روی **۲.۲ میلیون تراکنش واقعی پرداخت**، بینش‌های قابل اجرا برای پذیرندگان تولید می‌کند.

این پروژه برای **چالش زرین‌پال** ساخته شده و هدف آن کمک به پذیرندگان برای:

- درک بهتر الگوهای پرداخت
- بهبود نرخ موفقیت تراکنش‌ها
- شناسایی نقاط ضعف در فرآیند پرداخت
- تحلیل عملکرد PSPها و بانک‌ها
- کاهش درآمد از دست‌رفته

است.

<br />

> هدف پروژه فقط نمایش نمودار و KPI نیست؛  
> بلکه تبدیل **داده خام پرداخت** به **بینش قابل فهم و اقدام عملی** برای پذیرنده است.

## ✨ امکانات

### 📊 داشبورد اصلی

نمایی جامع از مهم‌ترین شاخص‌های عملکرد پرداخت با تمرکز بر خوانایی، سرعت و قابلیت تحلیل.

امکانات داشبورد اصلی:

- نمای KPI با نرخ موفقیت
- تعداد تراکنش‌ها
- مبلغ کل تراکنش‌ها
- درآمد از دست‌رفته
- نمودارهای تعاملی مقایسه PSPها
- مقایسه بانک‌ها
- تحلیل الگوهای ساعتی
- نمایش روندها و تفاوت‌های عملکردی

---

### 🔍 قابلیت ردیابی | Traceability

یکی از ویژگی‌های اصلی پروژه، قابلیت **Traceability** برای اعداد و تحلیل‌ها است.

روی هر عدد کلیک کنید تا جزئیات مربوط به نحوه محاسبه آن نمایش داده شود.

این جزئیات شامل موارد زیر است:

- فرمول محاسبه
- منطق Metric
- کوئری SQL
- داده مورد استفاده در محاسبه

به این ترتیب، نتایج داشبورد فقط یک عدد نهایی نیستند و امکان بررسی نحوه تولید هر نتیجه وجود دارد.

---

### 💡 بینش‌های هوشمند

بخش Insights با رویکرد **تحلیل فرضیه‌محور** طراحی شده است.

هر بینش شامل سه بخش اصلی است:

| بخش | توضیح |
|---|---|
| **فرضیه** | الگویی که در داده مشاهده شده است |
| **شواهد داده‌ای** | داده‌ها و Metricهایی که فرضیه را پشتیبانی می‌کنند |
| **اقدام پیشنهادی** | اقدامی که بر اساس نتیجه تحلیل پیشنهاد می‌شود |

هر بینش دارای یک توصیه اقدام مشخص است.

همچنین امکان گسترش جزئیات هر Insight وجود دارد تا کاربر بتواند موارد زیر را مشاهده کند:

- فرمول محاسبه
- SQL Query
- شواهد داده‌ای
- جزئیات تحلیل

### 🤖 دستیار هوش مصنوعی

بخش Chat یک دستیار هوش مصنوعی برای تحلیل داده‌های پرداخت در اختیار کاربر قرار می‌دهد.

کاربر می‌تواند به زبان طبیعی درباره داده‌ها سؤال بپرسد و دستیار بر اساس دیتاست پاسخ تولید کند.

نمونه سؤالات:

> کدام PSP نرخ موفقیت بهتری دارد؟

> کدام بانک بیشترین تراکنش ناموفق را داشته است؟

> در چه ساعت‌هایی بیشترین شکست پرداخت اتفاق می‌افتد؟

> کدام پذیرندگان بیشترین درآمد از دست‌رفته را دارند؟

> عملکرد یک PSP را در بانک‌های مختلف مقایسه کن.

---

#### 🛠 ابزارهای تحلیلی دستیار

دستیار هوش مصنوعی به **۱۱ ابزار تحلیلی** دسترسی دارد.

این ابزارها برای تحلیل بخش‌های مختلف دیتاست استفاده می‌شوند، از جمله:

- آمار کلی
- تحلیل PSP
- تحلیل بانک
- تحلیل پذیرندگان
- الگوی تلاش مجدد
- تحلیل وضعیت تراکنش‌ها
- تحلیل زمانی
- تحلیل مبلغ
- مقایسه عملکرد
- تحلیل ترکیبی داده‌ها
- اجرای کوئری SQL سفارشی

دستیار همچنین می‌تواند در صورت نیاز، **کوئری SQL سفارشی** برای پاسخ دادن به سؤال کاربر اجرا کند.

## 🚀 شروع

### 📋 پیش‌نیازها

برای اجرای پروژه به موارد زیر نیاز دارید:

- **Node.js 20 یا بالاتر**
- **npm**
- کلید API **AvalAI** یا **OpenAI**
- فایل CSV دیتاست چالش

---

### 1️⃣ دریافت پروژه

ابتدا Repository را Clone کنید:

```bash
git clone https://github.com/Hedyeh26/Zarinpal-Challenge.git
cd Zarinpal-Challenge
```

---

### 2️⃣ نصب وابستگی‌ها

```bash
npm install
```

---

### 3️⃣ پیکربندی

فایل Environment را ایجاد کنید:

```bash
cp .env.example .env.local
```

سپس فایل `.env.local` را ویرایش کنید و کلید API خود را قرار دهید:

```env
OPENAI_API_KEY=your-avalai-api-key-here
```

---

### 4️⃣ واردکردن داده

فایل CSV دیتاست چالش را در پوشه `data/` قرار دهید.

مسیر فایل باید به شکل زیر باشد:

```text
data/other_challenge_data.csv
```

سپس دستور زیر را اجرا کنید:

```bash
npm run db:import
```

این مرحله داده‌های CSV را وارد SQLite می‌کند تا امکان اجرای سریع‌تر Queryهای تحلیلی فراهم شود.

---

### 5️⃣ اجرای پروژه

برای اجرای Development Server:

```bash
npm run dev
```

پس از اجرا، برنامه در آدرس زیر در دسترس خواهد بود:

```text
http://localhost:3000
```

## 🗃 ساختار داده

دیتاست پروژه شامل **۲.۲ میلیون رکورد تراکنش** است.

فیلدهای اصلی دیتاست:

| فیلد | توضیح |
|---|---|
| `adjusted_amount` | مبلغ تراکنش (ریال) |
| `try_status` | وضعیت تلاش (Verified, Failed, InBank, etc.) |
| `try_seq` | شماره تلاش (0, 1, 2...) |
| `psp` | ارائه‌دهنده خدمات پرداخت |
| `bank_name` | نام بانک صادرکننده |
| `hour` | ساعت تراکنش |
| `date` | تاریخ تراکنش |

adjusted_amount

## 🔍 Traceability

یکی از اصول اصلی طراحی **ZarinPal Analytics**، شفافیت کامل در نحوه تولید نتایج است.

مسیر تولید یک تحلیل به شکل زیر قابل ردیابی است:

```text
Raw Transaction Data
        ↓
      Query
        ↓
      Metric
        ↓
     Formula
        ↓
     Evidence
        ↓
     Insight
        ↓
      Action
```

در نتیجه، کاربر می‌تواند از یک KPI یا Insight تا داده و Query تولیدکننده آن را بررسی کند.
